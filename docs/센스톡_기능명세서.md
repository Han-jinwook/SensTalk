# PART 2. 동적 수신자 명단 및 실시간 변수 치환 엔진

## 1. 명단 관리 및 영구 동기화
* **하드코딩 목업 전면 폐지:** 정적인 예시 목업 데이터를 완전히 들어내고, 사용자가 실제 입력/수정한 최신 명단만을 항상 유지.
* **로컬 스토리지 동기화 (`sensetalk_saved_recipients`):** 명단 업로드, 행 추가, 삭제, 수정 발생 즉시 브라우저 로컬 저장소에 영구 보관되어 새로고침 후에도 데이터 100% 유지.

## 2. 유저 파일 맞춤 동적 복합 컬럼(헤더) 파싱 규칙
* **임의 복합 컬럼 무제한 수용:** `이름`, `회사`, `직책`, `전화번호`, `메모`뿐만 아니라 `고객등급`, `계약일`, `만기일`, `포인트`, `환급액`, `예약시간` 등 유저가 업로드한 엑셀/CSV의 모든 컬럼명을 동적으로 인식하여 수신자 객체의 속성으로 매핑.
* **비문자열 데이터 타입(숫자/날짜) 무손실 보간:** 정수/실수/날짜형 데이터(예: `25000` ➔ `25000P`)를 유실 없이 문자열로 안전 형변환하여 치환.
* **컬럼명이 없는 파일 업로드 시 자동 유추 폴백:**
  - 1번째 컬럼 ➔ `이름`
  - 2번째 컬럼 ➔ `항목1` (전화번호 형식 감지 시 `전화번호`)
  - 3번째 컬럼 ➔ `항목2`
  - N번째 컬럼 ➔ `항목N`

## 3. 실시간 텍스트 변수 치환 엔진 (`getFullMessageForRecipient` / `get_blocks_for_recipient`)
* **치환자 문법:** `#{컬럼명}` (예: `#{이름}`, `#{고객등급}`, `#{포인트}`)
* **치환 규칙:**
  1. 수신자 데이터 객체에 해당 키가 존재하면 해당 값으로 즉시 치환.
  2. 일치하는 컬럼이 없는 경우 `#{컬럼명}` 원본 문자열을 깨뜨리지 않고 안전하게 보존.
  3. 광고 블록(`isAd: true`) 설정 시 `(광고)` 접두사 및 `무료수신거부: {optOutNum}` 번호 자동 부착.

## 4. 글로벌 연락처 자동 정규화 엔진 (`get_recipient_phone`)
* **다변화된 연락처 헤더 통합 파싱:** `phone`, `전화번호`, `연락처`, `휴대폰`, `핸드폰`, `mobile`, `tel` 중 존재하는 필드를 자동 탐색하여 추출.
* **국제전화 번호 자동 변환 (WhatsApp 전용):** `010`, `011`, `016` 등 `01`로 시작하는 국내 모바일 번호의 맨 앞 `0`을 제거하고 국가코드 `82`를 붙여 `8210...` 형식으로 100% 자동 변환.

## 5. 수신자 명단 테이블 4대 핵심 컬럼 초슬림화 및 노이즈 데이터 자동 정제
* **기존의 복잡한 다단 컬럼 소거:** 사용자 화면을 어지럽히던 불필요 변수(`포인트`, `가입링크`, `질환명`, `메모` 등)를 테이블 본문에서 과감히 제거.
* **4대 핵심 컬럼 집중:**
  1. `성명/호칭`: 고객 이름 및 직함 (예: `홍길동 대표님`)
  2. `연락처/식별`: 휴대폰 번호 또는 회원 식별 ID
  3. `상태`: 뱃지 클릭으로 `대기` ➔ `완료` ➔ `패스` 순환 토글 (완료 시 바운스 팝 도장 애니메이션 구동)
  4. `제외`: 명단에서 해당 인원을 1초 만에 제외(`deleteRecipient`)
* **노이즈 데이터 자동 필터링:** 엑셀 등에서 유입된 `'없음'`, 빈칸, 특수기호 등 가독성을 해치는 더미 텍스트를 실시간으로 정제하여 깔끔한 시야 확보.
* **명단 전원 일괄 비우기 (`clearAllRecipients`):** 확인 대화상자 안전 장치와 함께 현재 명단 전체를 원클릭으로 초기화.

## 2. 다중 블록(Multi-Block) 순차 발송 엔진 메커니즘
1. **블록 시퀀스 구성 (`get_blocks_for_recipient`):**
   - 수신자별로 치환이 완료된 유효 텍스트 블록과 base64 이미지 데이터를 원본 순서 그대로 배열 리스트로 빌드.
2. **동일 대화방 내 순차 전송 루프:**
   - **블록 0 장전:** 대화방 오픈 및 첫 번째 블록(텍스트) 장전 ➔ `WAITING_FOR_USER_ENTER = True`.
   - **1차 [Enter] 타건 감지:** 대화방을 닫지 않고 유지 ➔ 다음 블록 유무 확인.
   - **블록 1(사진) 자동 주입:** `0.4~1.0초` 휴먼 지터 후 Windows 클립보드(`CF_DIB`) 장전 ➔ `Ctrl + V` 타건 ➔ 사진 전송 모달 안착 ➔ `WAITING_FOR_USER_ENTER = True`.
   - **2차 [Enter] 타건 감지:** 최종 사진 전송 확정 ➔ 수신자 `done` 갱신 ➔ `sent_and_advancing` 발행.
   - **창 닫기 및 전진:** 카카오톡의 경우 자동 오픈 대화창 ESC 닫기 ➔ 다음 대기 고객 자동 로드.

## 3. Windows 클립보드 비트맵(`CF_DIB`) 자동 주입 메커니즘
* **표준 비트맵 변환 파이프라인:**
  - Base64 DataURL (PNG/JPEG) ➔ Pillow(PIL) 디코딩 ➔ 24-bit RGB BMP 변환 ➔ 14바이트 `BITMAPFILEHEADER` 제거 ➔ 순수 `CF_DIB` 바이너리 스트림 추출.
  - Windows 클립보드에 `CF_DIB` 포맷으로 안전 등록 (`win32clipboard` 또는 Win32 API `SetClipboardData`).
* **마우스 드래그 0% 전 채널 네이티브 호환:**
  - 텔레그램, 라인, 왓츠앱, 위챗, SMS(휴대폰과 연결), 카카오톡 모두 Windows 클립보드의 `CF_DIB` 비트맵을 `Ctrl + V` 단축키로 수신하여 자체 사진 미리보기/전송 화면을 즉시 띄움.

## 4. 휴먼 지터(Human-like Jitter) 8대 영역 무작위 난수화 보안 엔진
기계적 매크로 고정 딜레이(Fixed Milliseconds)를 전면 폐지하고 사람 특유의 가변적 물리 반응 시간을 모사하여 안티봇/휴리스틱 탐지 원천 차단:

| 영역 | 동작 내용 | 적용된 휴먼 지터 난수 범위 | 보안 방어 목적 |
| :---: | :--- | :---: | :--- |
| **1** | **키보드 단일 타건 (`press_key`)** | `0.025초 ~ 0.065초` (25~65ms) | 손가락 누름 압력 및 릴리즈 시간의 물리적 불규칙성 재현 |
| **2** | **단축키 조합 (`press_hotkey`)** | `Ctrl` 누름 `20~50ms`, `V` 누름 `25~65ms` | 복합 단축키 타건 시 인간 손가락의 미세 시차 재현 |
| **3** | **블록 간 전송 텀 (텍스트 ➔ 사진)** | **`0.4초 ~ 1.0초`** 완전 난수 | 이전 말풍선 전송 확인 후 다음 사진을 올리는 인간 반응 시차 |
| **4** | **수신자 완료 후 다음 대상 전진 텀** | **`0.35초 ~ 0.75초`** 완전 난수 | 한 사람 완료 후 다음 대상을 부르는 자연스러운 호흡 리듬 |
| **5** | **마우스 클릭 & 포커스 안착** | 클릭 다운/업 `15~35ms`, 포커스 대기 `40~80ms` | 마우스 버튼 물리적 누름 및 윈도우 포커스 반응 지터 |
| **6** | **메시지 붙여넣기 렌더링 대기** | `0.14초 ~ 0.24초` 난수 | 메신저 텍스트 프레임워크의 입력 감지 대기 시차 분산 |
| **7** | **창 전환 및 포그라운드 활성화** | `0.09초 ~ 0.16초` 난수 | Windows OS 데스크톱 핸들 스위칭 반응 시차 가변화 |
| **8** | **친구 검색 및 1:1 대화방 오픈** | 검색 `80~150ms`, 대화창 팝업 `420~650ms` | 검색창 활성화 및 대화방 팝업 대기시간 불규칙화 |

## 5. 지능형 창 닫기 정책 (Smart ESC)
* 대량 발송 시 봇이 자동 오픈한 중간 수신자 창만 ESC로 깔끔히 닫아 바탕화면 창 범람 방지.
* 유저가 수동으로 미리 열어둔 대화창(`_pre_opened: true`)이거나 마지막 대상일 때는 전송 후 대화창을 닫지 않고 유지.

# PART 6. 안전 및 예외 처리 정책

1. **Human-in-the-loop 원칙:**
   - 최종 전송 결정은 사용자가 대화창을 확인하고 물리적 [Enter]를 누름으로써 이루어지므로, 메신저사의 무차별 백그라운드 봇 탐지 알고리즘을 원천 회피.
2. **명단 완료 시 자동 발송 차단 정책 (All-Done Safety Lock):**
   - 명단 전체의 발송 상태가 `done`인 경우 시작 버튼이 비활성화되며 발송이 차단됨.
   - 상단 [🔄 상태 초기화] 버튼을 명시적으로 눌러야만 `pending`으로 리셋되어 재발송 가능.
3. **비상 정지 (`[F9]`):**
   - 발송 도중 예기치 못한 상황(오타, 오발송 위험 등) 발생 시 즉시 키보드 `[F9]`를 누르면 0.01초 내로 엔진 루프 정지.
4. **F8 전역 단축키 수동 제어:**
   - 윈도우 전역 핫키 `[F8]`을 등록하여 마우스 조작 없이도 발송 시작 및 강제 다음 대상 전진 가능.
5. **안티밴 일일 한도 강제 (Daily Limit Guard):**
   - 로컬 파일(`bot_stats.json`)에 일자별 발송량을 누적 기록하여, 1일 최대 500건 초과 시 하드 리밋에 의해 발송 자동 중단.

# PART 7. 자주 쓰는 상용구(텍스트 & 이미지) 서랍 및 레고 블록 믹스 (Lego Assembly)

## 1. 개요 및 목적
* **공수 90% 절감:** 반복되는 인사말, 계좌번호, 배송/송장 안내, 램프 교체 가이드, A/S 접수 절차 및 안내 이미지 카드를 서랍에서 꺼내 즉시 조립.
* **비파괴 즉석 편집 (Non-destructive):** 상용구를 캔버스에 꽂은 후 특정 단어를 고객에 맞게 수정해도 원본 상용구 데이터는 100% 안전 유지.

## 2. 7대 카테고리 체계
1. `전체`: 모든 상용구 통합 뷰
2. `🖼️ 이미지`: 제품 안내도, 가이드 카드, 계좌 사진 등 이미지/사진 상용구
3. `💬 인사`: 기본 안부 및 정기 인사말
4. `💳 계좌/결제`: 무통장 입금 계좌 및 계산서 안내
5. `📱 썬드리머앱`: 공식 웹앱 간편가입, 5,000P 혜택 및 일기/스토어 안내
6. `💡 램프/제품`: 제품 사용법 및 권장 교체주기 가이드
7. `🔧 AS/점검`: 기기 이상 및 본사 A/S 접수 절차
8. `📁 일반`: 기타 공용 상용구

## 3. 투트랙(Two-Track) 삽입 메커니즘
* **방식 A (신규 블록 조립 - `[+ 블록추가]`):**
  - 상용구를 캔버스 최하단에 새로운 독립 블록(텍스트 또는 이미지 블록)으로 즉시 추가.
  - 마우스 드래그 또는 순서 변경을 통해 자유로운 레고식 메시지 결합 지원.
* **방식 B (커서 위치 삽입 - `[📍 커서삽입]`):**
  - 현재 캔버스에서 편집 중인 텍스트에어리어(`textarea`)의 커서(Selection) 위치에 텍스트 문구만 쏙 끼워 넣기.

## 4. 즉석 상용구 등록 편의장치 및 최신 모핑 아코디언 UI/UX
* **블록 헤더 `[⭐️ 상용구 보관]`**: 캔버스에서 작성한 텍스트 또는 등록한 이미지를 원클릭으로 상용구 서랍에 즉시 저장.
* **Linear & Dynamic Island 스타일 모핑 아코디언 (100% 브라우저 호환 60fps 무지연 슬라이딩):**
  - 기존의 덜컹거리는 `display: none`과 flex 컨테이너에서 취약한 CSS Grid 트랙을 전면 개선하여, `max-height`(0 ➔ 420px) 가속 트랜지션 및 `hidden` 토글 결합 아키텍처 적용.
  - **접힘 시:** 우측 컴팩트 알약 캡슐(Amber Gold Pill, `w-auto max-w-max`, `whitespace-nowrap`)로 슬림 수축되어 글자 찌그러짐 없이 높이 32px의 세련된 캡슐 유지.
  - **펼침 시:** 좌측 들여쓰기 굵은 악센트 테두리(`border-l-[6px]`)와 깨끗한 화이트 배경의 풀 와이드 카드 서랍(700px+)으로 0.3초 만에 쫀득하게 모핑 전개.
* **로컬 영구 동기화 (`sensetalk_snippet_library`):** 브라우저 새로고침 후에도 등록/수정한 상용구 100% 보존.
* **상용구 등록/수정 모달 안정화 및 반응형 뷰포트 방어 시스템:**
  - 텍스트/이미지 유형 및 내용 길이에 상관없이 `max-h-[88vh]`와 본문 `overflow-y-auto` 스크롤 격벽을 적용하여 헤더(제목, 닫기)와 푸터(취소, 서랍에 저장)가 화면 밖으로 이탈하지 않도록 영구 고정.
  - SVG/이미지 에셋의 Base64 안전 정규화 및 DOM 썸네일 고정 크기(`w-16 h-16`) 보장으로 이미지 미리보기 태그 깨짐 및 모달 비대화 원천 차단.
  - 최상위 z-index(`z-[70]`) 격상으로 퀵 가이드나 플로팅 위젯의 모달 덮임 현상 완전 해소.

# PART 8. 모던 마이크로 인터랙션 & 햅틱 피드백 시스템 (Micro-Interactions)

## 1. 카톡 미리보기 수신자 전환 골드 글로우 펄스 (`varGlowPulse`)
* `[A]` / `[D]` 또는 좌우 화살표(`←` / `→`) 키로 수신자를 전환할 때마다, 본문 속 치환 변수(`#{이름}`, `#{직함}` 등)가 0.45초간 은은하게 반짝이는 앰버 골드 글로우 펄스 애니메이션 구동.
* 발송자가 고객별 맞춤 변수가 정상 치환되었는지 눈으로 직관적이고 빠르게 검증 가능.

## 2. `[Enter]` 발송 버튼 햅틱 리플 (`btnRippleWave`)
* 메인 발송 버튼 클릭 또는 텍스트 입력창 밖에서 `[Enter]` / `[Space]` 타건 시 버튼 외곽으로 은은한 골드 파동이 퍼지는 리플 피드백 제공 (키보드 타건 리듬감 극대화).

## 3. 수신자 명단 완료 도장 바운스 팝 (`badgePopStamp`)
* 복사 완료(`copyMessageAndAdvance`) 또는 상태 수동 변경 시, 해당 수신자의 상태 뱃지('완료')가 도장 찍히듯 톡 튀어오르는 바운스 팝 애니메이션 연동.

## 4. 캔버스 레고 블록 단일 확장(Single-Open) 동적 아코디언 및 텍스트박스 최적화
* **복수 블록 시 1개 블록 단일 열림 유지:** 블록이 2개 이상 복수로 존재할 때 화면 공간을 효율적으로 활용하기 위해 무조건 1개 블록만 열림 상태를 유지하며, 다른 블록을 선택(클릭)하면 기존에 열려있던 블록은 자동으로 닫힘.
* **새 블록 추가 시 자동 포커스 열림:** 텍스트/이미지 블록 추가 또는 상용구 조립 시 기존 블록은 자동으로 접히고 새로 추가된 블록만 열림 유지.
* **맞춤 변수 섹터 헤더 상단 배치:** 텍스트 블록의 맞춤 변수 칩 바(`+#{이름}`, `+#{직함}` 등)를 본문 내부에서 블록 상단 헤더 줄로 이동 배치하여 텍스트박스의 세로 높이 공간을 최대로 확보.
* **텍스트박스 무한 자동 확장 및 글자 크기 최적화:** 단일 블록 열림 구조에 맞춰 텍스트박스 내부 스크롤바 없이(`overflow-hidden`, `resize-none`) 입력된 글자 수 및 줄 수에 따라 아래로 무한 자동 확장(`autoResizeTextarea`), 글자 크기를 12px(`text-[12px]`)로 축소하여 가독성과 공간 효율 극대화.
* **드래그 핸들 전용 이동 격리 (텍스트 선택 충돌 방지):** 텍스트 입력창 내부에서 글자를 드래그하여 선택할 때 상위 블록 카드가 이동하는 오류를 원천 차단하기 위해 카드 본체는 기본 `draggable=false`로 잠금 격리하고, 오직 좌상단 점 6개 핸들(`drag_indicator`)을 잡았을 때만 블록 순서 이동이 동작하도록 보호 로직 연동.
* **드래그 앤 드롭 실시간 삽입 가이드라인 (드롭 인디케이터):** 블록을 드래그하여 이동할 때 놓을 지점을 직관적으로 인지할 수 있도록, 텍스트 군더더기 없이 삽입 대상 슬롯 사이에 슬림하고 선명한 인디고 글로우 빔 가이드라인(`●━━━━━━━━━━━━━━━━●`)이 실시간으로 하이라이팅 표시되는 미니멀 시각적 피드백 시스템 연동.
* **순수 CSS Grid 60fps 무지연 모션:** 블록 접기/펼치기 토글 시 60fps 슬라이드 애니메이션 연동.

# PART 9. 루미노트 CRM 대기열 실시간 연동 및 원클릭 일괄 장전 시스템 (CRM Queue Sync)

## 1. 기획 배경 및 연동 목적
* **포인트/신규 고객 실시간 알림 파이프라인:** 루미노트 및 썬드리머 웹앱에서 포인트가 등록되었거나 신규 가입한 고객들의 발송 대기열을 센스톡으로 원클릭 수신하여 1:1 맞춤 카톡/문자 발송을 즉시 실행.
* **복붙 공수 제로화:** 관리자 페이지에서 엑셀을 내려받아 센스톡에 다시 올리는 번거로움 없이 클라우드 DB에서 직접 1초 만에 장전.

## 2. Supabase DB 실시간 동기화 아키텍처
* **대기열 테이블 규격:** `sensetalk_notification_queue`
  - `id`: 고유 큐 레코드 ID
  - `name`: 고객 성명 / 카페 닉네임
  - `phone`: 연락처
  - `status`: `pending` (대기), `completed` (발송완료), `cancelled` (제외)
  - `metadata`: 포인트 지급 내역, 가입일, 소개자 정보 등
* **헤더 실시간 뱃지 감지 (`updateCrmQueueBadge`):**
  - 센스톡 화면 상단 액션바에 `[✉️ CRM 대기열 N명]` 뱃지가 실시간 미처리 인원수를 표시.
* **원클릭 일괄 장전 모달 (`openCrmQueueModal`):**
  - 복잡한 필터 탭 없이 대기열 명단을 실시간 조회 후 `[📥 대기열 전원 일괄 장전]` 클릭 즉시 센스톡 수신자 명단 테이블에 자동 주입.

## 3. 양방향 상태 피드백 및 배지 자동 소멸
* **발송 완료 시 (`status: completed`):**
  - 단일 발송 또는 PC 엔진 연속 발송 루프 완료 시, Supabase DB에 `status = 'completed'` PATCH 요청 전송 ➔ CRM 대기열 배지 즉시 차감 및 자동 소멸.
* **명단 개별 제외 시 (`status: cancelled`):**
  - 수신자 테이블에서 특정 고객 제외(`deleteRecipient`) 시 DB에 `status = 'cancelled'` 자동 반영하여 중복 발송 방지.

# PART 10. 범용 필드 기반 스마트 조건부 발송 엔진 (Smart Conditional Skip)

## 1. 특정 서비스 종속 탈피 & 범용 조건식 개편
* **과거 한계 극복:** 특정 웹앱(썬드리머 등)에 하드코딩되었던 전용 버튼과 고정 필터를 전면 폐지.
* **동적 필드 자동 추출:** 업로드된 엑셀/CSV 또는 CRM 대기열의 실제 필드명(`가입여부`, `앱가입`, `고객등급`, `성별`, `지역` 등)을 실시간으로 읽어와 조건 선택 드롭다운에 자동 매핑.

## 2. 조건부 타겟팅 바 (`_dispatchCondition`) 메커니즘
* **3단계 조건식 구성:**
  - `[타겟 필드]` (예: `가입여부`) + `[비교 연산자]` (`=`, `!=`, `포함`, `미포함`) + `[기준값]` (예: `가입` or `O`)
* **지정 블록 자동 스킵(패스):**
  - 조건식에 일치하는 수신자에게는 특정 블록(예: B1 블록 "앱 가입 안내문")을 **자동 발송 제외(스킵)** 처리.
  - 조건 미일치 수신자에게는 모든 블록이 정상 순차 발송됨.

## 3. 단일 메인 발송 버튼 일원화 (`handleUnifiedDispatchClick`)
* **원버튼 완결:** "일반 발송"과 "조건부 발송" 버튼을 구분하지 않고, 단 하나의 메인 발송 버튼(`[⚡ 엔터 연속 발송]` / `[📋 클립보드 복사]`)으로 통합.
* **스마트 분기:** 조건식 활성화 여부에 따라 백그라운드에서 자동으로 블록을 선별하여 전송.

## 4. 실시간 카톡 미리보기 안심 검증
* **조건 일치 자동 패스 뱃지:** 조건에 부합하는 수신자를 선택하거나 넘겨볼 때, 카카오톡 실시간 스마트폰 화면에 노란색 앰버 안내 바(`filter_alt B1 블록은 조건 일치 자동 패스`)를 띄워 발송자가 눈으로 즉시 확인 가능.

## 3. [기능 2] AI 톤앤매너 조율사 (One-Click Tone Transformer)
* **4대 감성 톤 원클릭 변환:**

  - `따뜻한 감성 안부체`: 고객과의 유대감을 높이는 다정한 대화체

# PART 12. 안티그래비티 스타일 1-클릭 엔진 자체 업데이트 시스템 (Engine Self-Update v2.7)

## 1. 아키텍처 비전: "수동 zip 다운로드/압축해제 0회 달성"
* **기존의 한계:** 새 엔진 버전 출시 시 사용자가 zip을 다운로드받아 수동 압축 해제하고 기존 콘솔을 닫고 다시 실행해야 하는 번거로움 존재.
* **혁신 달성:** 안티그래비티(Antigravity) / VS Code 방식으로 브라우저에서 버튼 1회 클릭만으로 백그라운드 핫스왑 및 무중단 자체 재실행(In-Place Restart) 완료.

## 2. 엔진 자체 업데이트 엔드포인트 (`bot/sensebot.py`)
* **API 라우트:** `POST http://127.0.0.1:28888/self-update`
* **멀티 미러 원격 다운로드 파이프라인:**
  1. 1순위: 공식 GitHub Raw 저장소 (`https://raw.githubusercontent.com/Han-jinwook/SensTalk/main/bot/sensebot.py`)
  2. 2순위: Netlify 초고속 CDN 미러 (`https://sensetalk.netlify.app/sensebot.py`)
* **구문 무결성 사전 검증 (Syntax Check):**
  - 파이썬 `compile(code, "<updated_sensebot>", "exec")`을 통해 문법 검증 통과 시에만 적용.
* **원자적 백업 및 교체 (Hot-Swap):**
  - 기존 실행 파일을 `sensebot.py.bak`으로 즉시 백업 후 신규 코드로 덮어쓰기.
* **독립 콘솔 인플레이스 재기동 (Decoupled Restart):**
  - 브라우저에 성공 응답(200 OK)을 안전하게 먼저 전송.
  - Windows `start` 명령어를 통해 독립된 새 콘솔 프로세스를 백그라운드 기동하고, 기존 프로세스는 `os._exit(0)`으로 즉시 종료하여 포트 28888을 안전하게 바통 터치.

## 3. 웹 UI 원클릭 업데이트 제어 (`ui/app.js` & `ui/index.html`)
* **원클릭 업데이트 트리거 (`requestEngineSelfUpdate`):**
  - 버튼 클릭 즉시 로딩 스피너 및 단계별 안내 토스트 표시 (`최신 엔진 다운로드 및 교체 중...`).
  - 1초 간격으로 새 엔진 기동 상태(`/health`) 자동 폴링.
  - 새 버전 응답 감지 시 모달 자동 닫힘 및 축하 토스트 노출.
* **하위 호환성 예외 처리 (Graceful Fallback):**
  - 실행 중인 엔진이 구버전(v2.5 등)이라 `/self-update`가 없는 경우, 사용자에게 친절한 1회성 안내 및 zip 다운로드 지원.
* **2대 안전 버튼 구성:**
  - `[ ⚡ 🚀 1초 원클릭 자동 업데이트 (권장) ]`: 에메랄드 그라디언트 기본 액션 버튼.
  - `[ 📁 수동 zip 다운로드 ]`: 오프라인 환경을 위한 보조 다운로드 링크.

# PART 13. 모바일 전용 온보딩 랜딩 뷰 및 PC 접속 가이드 시스템 (Mobile Onboarding Landing View)

# PART 14. 텍스트 박스 최적화 동적 메커니즘 및 캔버스 조작성 극대화

## 1. 복수 블록 배타적 단일 열림 원칙 (Single Active Accordion)
* **도입 배경:** 캔버스에 블록이 2개, 3개 이상 늘어날 때 모든 블록이 펼쳐져 있으면 세로 스크롤 압박이 심해지고, 작업 집중도가 저하되는 문제 해결.
* **배타적 열림 메커니즘:**
  - 캔버스 내 복수 블록 존재 시 **무조건 1개만 열림** 상태를 유지.
  - 다른 블록의 헤더를 클릭하여 펼치면 기존에 열려있던 블록은 자동으로 접힘(`isCollapsed = true`).
  - 새 블록 추가(`addTextBlock`, `addImageBlock`) 또는 상용구 조립(`insertSnippetAsNewBlock`) 시에도 기존 블록을 일괄 닫고 새 블록만 열림 상태로 포커스.

## 2. 맞춤 변수 칩 바 윗줄(헤더) 전진 배치
* **공간 극대화:** 기존에 텍스트 본문 영역 상단을 차지하던 `#{이름}`, `#{직함}` 등의 변수 칩 바를 **블록 헤더 윗줄(우측)**로 이동 배치.
* **효과:** 본문 텍스트 박스의 상단 여백을 온전히 확보하여 메시지 작성 및 가독성 영역을 대폭 확대.
* **접힘 상태 자동 은닉:** 블록이 접혔을 때는 변수 바를 숨기고 한 줄 요약 프리뷰(`block-summary-preview`)로 자연스럽게 대체.

## 3. 글자수 비례 무한 자동 신축 텍스트 박스 (Auto-Expanding Textarea)
* **내부 스크롤바 제거:** 텍스트 박스 내부의 답답한 이중 스크롤바(`overflow-hidden`, `resize-none`)를 완전히 배제.
* **글자수에 따른 무한 확장:** 사용자가 텍스트를 입력하거나 변수를 삽입할 때 `textarea.scrollHeight`를 실시간 측정하여 텍스트 전체가 한눈에 보이도록 아래로 자연스럽게 늘어남 (`autoResizeTextarea`).
* **초기 렌더링 동기화:** 템플릿 로드 시 `requestAnimationFrame`을 통해 작성된 글자 길이에 맞춰 즉시 알맞은 높이로 자동 신축.

## 4. 텍스트 박스 내부 드래그 선택 시 DnD 간섭 원천 차단
* **문제점:** 텍스트 입력창 내부에서 특정 단어나 문장을 마우스로 드래그 선택하려 할 때, 상위 카드의 드래그 앤 드롭(DnD) 핸들러가 오작동하여 카드가 이동하려던 현상.
* **해결 방안:**
  - 텍스트 입력 영역(`textarea`) 및 이미지 드롭존 클릭/선택 시 `window._dragActiveHandle = false` 및 `blockEl.draggable = false`를 강제 적용하고 `mousedown` / `dragstart` 이벤트 전파를 차단(`e.stopPropagation()`).
  - 블록 이동은 오직 좌측 상단의 점 6개 드래그 핸들(`drag_indicator`)을 명시적으로 잡았을 때만 활성화되도록 완벽히 격리.

## 5. 최적 가독성 폰트 크기 미세 조정 (-1px)
* 텍스트 본문 기본 글자 크기를 `12px`(`text-[12px] font-mono leading-relaxed`)로 1단계 축소하여 긴 메시지 작성 시에도 시야 확보 및 공간 효율을 극대화.

# PART 18. 메시지 템플릿 & 수신자 명단 동적 저장 버튼 활성화 메커니즘 (`saveTemplateBtn`, `saveRecipientsBtn`)

3. **저장 완료 (Saved / Clean):**

   - 텍스트: `"저장됨"`, 아이콘: 선명한 에메랄드 체크마크(`check_circle`).
   - 사용자가 원할 경우 언제든 클릭하여 다른 이름으로 추가 저장하거나 덮어쓰기 가능.

# PART 19. 브라우저 세로 리사이즈 반응형 수신자 명단 신축 및 발송 도크 보존 메커니즘

## 1. 문제 해결 배경
* **기존 문제점:** 브라우저의 창 높이(세로폭)를 줄였을 때, 수신자 명단 테이블이 고정 비율(`h-[68%]` 및 `shrink-0`)을 고집하여 하단 발송 도크(카톡 미리보기, 채널 탭, 노란색 연속 발송 버튼)를 밀어내며 아래쪽부터 화면 밖으로 잘려 나가는 심각한 사용성 문제 발생.
* **사용자 요구사항:** 창 높이가 줄어들면 가장 핵심인 하단 발송 도크가 잘리는 것이 아니라, 줄어든 폭만큼 상단 **'수신자 명단 테이블'의 아래쪽 여백이 유연하게 줄어들어야 함**.

## 2. 반응형 신축 레이아웃 아키텍처
* **수신자 명단 테이블 영역 (`flex-1 min-h-0`):**
  - 고정 `h-[68%]` 및 `shrink-0`를 완전히 제거하고, 가변 유연 축소 속성(`flex-1 min-h-0`)으로 전면 전환.
  - 내부 테이블 스크롤 래퍼(`#recipientListScrollWrapper`) 역시 `flex-1 min-h-0 overflow-y-auto`로 구성하여 창 높이가 줄어들면 명단 하단 여백이 먼저 줄어들고, 데이터가 많을 때는 자체 세로 스크롤바로 원활히 탐색 가능.
* **발송 통제 도크 영역 (`shrink-0`):**
  - 기존의 `flex-1 min-h-0 overflow-hidden`을 배제하고 `shrink-0`로 설정.
  - 뷰포트 높이가 580px 이하로 좁아지더라도 카톡 미리보기, 5종 채널 탭, 발송 조건 바, 메인 연속 발송 버튼(`[💬 카카오톡 연속 발송 시작 [Enter키]]`), 패스, 엔진 상태 뱃지가 **단 1픽셀도 잘림 없이 100% 완전 노출** 유지.

# PART 20. 메시지 블록 캔버스 세로폭 반응형 동적 상한선(Max Height) 및 하단 추가 버튼 보존 메커니즘

## 1. 문제 해결 배경
* **기존 문제점:** 우측 '메시지 블록 캔버스'에서 텍스트 블록의 글자 수가 많아질 때, 높이가 무한정 아래로 늘어나면서 브라우저 창 높이가 줄어들면 맨 하단의 핵심 추가 버튼(`[+ 텍스트 블록 추가]`, `[+ 이미지(사진) 추가]`)이 화면 밖으로 밀려나 사라지는 현상 발생.
* **사용자 요구사항:** 창 세로폭이 줄어들더라도 맨 하단의 추가 버튼들이 밀려나 사라지지 않도록, 열려있는 텍스트박스가 잔여 가용 세로 높이에 맞춰 더 이상 무제한으로 커지지 않게 동적 상한선(Cap)을 적용하고 내부 스크롤로 처리할 것.

## 2. 동적 최대 높이 계산 아키텍처 (`calculateTextareaMaxHeight`)
* **캔버스 가용 높이 정밀 산출:**
  $$\text{Available Space} = H_{\text{container}} - P_{\text{container}} - \sum H_{\text{otherChildren}} - H_{\text{currentBlockOverhead}} - \text{SafetyBuffer}$$
  - $H_{\text{container}}$: `#blocksCanvasContainer.clientHeight`
  - $P_{\text{container}}$: 캔버스 상하 패딩(`paddingTop + paddingBottom`)
  - $\sum H_{\text{otherChildren}}$: 현재 열린 블록을 제외한 다른 모든 접힌 블록들 및 맨 하단 추가 버튼 바의 실제 높이 + 상하 마진 총합
  - $H_{\text{currentBlockOverhead}}$: 현재 블록 내부의 비(非) 텍스트 영역(카드 헤더, 맞춤 변수 바, 패딩, 보더, 마진 등 실측 84px+)
  - $\text{SafetyBuffer}$: 서브픽셀 렌더링 오차 방지 및 쾌적한 여백을 위한 20px 안전 버퍼
  - **최소 높이 보장:** 계산된 가용 높이가 극단적으로 작아지더라도 기본 3줄 분량(`76px`)은 항상 보장.

## 3. 스마트 자동 신축 및 내부 스크롤 전환 메커니즘 (`autoResizeTextarea`)
1. **내용이 적을 때 (`naturalHeight <= maxHeight`):**
   - 글자 수에 맞추어 본문 높이가 자연스럽게 늘어나며, 스크롤바 없는 매끄러운 텍스트 입력 경험 제공 (`overflowY = 'hidden'`).
2. **내용이 세로 상한선을 초과할 때 (`naturalHeight > maxHeight`):**
   - 텍스트박스 높이가 계산된 `maxHeight` 상한선에서 정확히 정지.
   - 내부 세로 스크롤바가 자동 활성화되어 장문의 메시지도 텍스트박스 안에서 부드럽게 스크롤 가능 (`overflowY = 'auto'`).
   - 캔버스 자체(`#blocksCanvasContainer`)는 스크롤이 발생하지 않아 맨 하단 추가 버튼들이 뷰포트 내에 영구 고정 노출.
3. **창 크기 조절 시 실시간 반응형 동기화:**
   - `window.addEventListener('resize')` 이벤트에서 열려있는 모든 텍스트박스를 재계산하여 창 높이를 늘리거나 줄일 때 즉각적으로 높이 확장/축소 적용.

## 4. UI 및 시각 디자인 최적화
* **미려한 5px 초슬림 스크롤바 (`::-webkit-scrollbar`):** 텍스트박스 내부 스크롤 발생 시 슬림한 반투명 필(Pill) 스타일 스크롤바 적용.
* **캔버스 하단 불필요 여백 다이어트:** `#blocksCanvasContainer`의 기존 `pb-8`(32px)을 `pb-3 sm:pb-4`(12~16px)로, `addBtnCard`를 `pt-1 pb-1 sm:pb-2`로 최적화하여 텍스트박스에 약 45px 이상의 추가 수직 표시 공간 확보.

## 5. 실시간 커서 추적 및 본문 하단 자동 스크롤 동기화 (`scrollTextareaToCursor`)
* **문제 해결 배경:** 텍스트박스가 최대 높이 상한선에 도달하여 내부 스크롤이 활성화된 상태에서 새 글을 추가하거나 타이핑할 때, 높이 재계산 시 `scrollTop`이 0으로 초기화되면서 화면이 맨 위로 튀어 현재 작업 중인 커서 및 하단 글이 시야에서 가려지는 현상 완벽 방지.
* **커서 위치 및 스크롤 상태 사전 보존:**
  - `autoResizeTextarea` 실행 시 `prevScrollTop`, `isAtBottom`, `cursorAtEnd`를 사전 포착.
  - 커서가 맨 끝에 있거나 본문 하단에서 작업 중인 경우(`cursorAtEnd || isAtBottom || options.scrollToEnd`), `textarea.scrollTop = textarea.scrollHeight`로 즉각 하단 정렬.
  - 본문 중간에서 수정 중인 경우 기존 스크롤 위치(`prevScrollTop`)를 오차 없이 복원하여 상단 튐 현상 원천 차단.
* **정밀 커서 추적 뷰포트 정렬 (`scrollTextareaToCursor`):**
  - 타이핑(`oninput`), 방향키/키보드 이동(`keyup`), 마우스 클릭(`click`) 시 커서가 위치한 줄(Line)의 좌표를 정밀 산출하여 커서가 항상 화면 가시 영역 중앙~하단에 보이도록 자동 추적.
* **상용구 및 맞춤 변수 삽입 연동:**
  - 상용구 `[커서삽입]` 및 맞춤 변수 칩 클릭 시 삽입된 위치로 커서를 이동하고 즉시 스크롤을 동기화하여 방금 삽입된 내용을 사용자가 바로 확인 가능.

# PART 21. 스마트 조건부 타겟팅 발송 및 무손실 영구 보관 메커니즘

## 1. 개발 배경 및 목적
* **엑셀 재가공 불필요:** 대량 명단 중 특정 세그먼트(예: `고객등급 == VIP`, `포인트 >= 10000`, `가입경로 == 인스타`)에게만 선별 발송하고자 할 때, 엑셀을 일일이 필터링하여 새로 업로드하거나 수동으로 행을 제외하던 번거로움을 완전히 해결.
* **유연한 다이나믹 조건식:** 업로드된 엑셀/CSV의 모든 컬럼명을 동적으로 인식하여 사용자가 원하는 임의의 조건식을 손쉽게 조합하고, 조건에 부합하는 수신자만 발송 루프에 포함시키며 불일치 인원은 자동 패스 처리.

## 2. 동적 필드 추출 및 지능형 비교 연산자 엔진
* **명단 맞춤 동적 필드 셀렉터:**
  - 업로드된 명단의 실제 헤더(`성명`, `전화번호`, `포인트`, `고객등급`, `지역` 등)를 자동 감지하여 드롭다운 목록으로 실시간 렌더링.
* **7대 정밀 비교 연산자:**
  1. `== (같음)`: 문자열/숫자 완전 일치 판별.
  2. `!= (다름)`: 일치하지 않는 대상 선별.
  3. `>= (이상)`, `<= (이하)`: 정수/실수/날짜형 숫자 크기 비교 (숫자 외 텍스트를 제거하고 안전하게 수치 변환).
  4. `> (초과)`, `< (미만)`: 엄격한 대소 관계 비교.
  5. `포함 (contains)`: 텍스트 부분 일치 검색.

## 3. 오타 방지 기준값 샘플 칩(Chip) 및 0명 일치 안전 경고 시스템
* **실시간 고유값 추출 샘플 칩 (Sample Chips):**
  - 선택된 필드에 실제로 존재하는 명단 데이터의 고유값(Unique Values)을 실시간으로 분석하여 최대 5개의 클릭 가능한 뱃지(칩)로 제공.
  - 사용자가 키보드로 기준값을 일일이 타이핑할 필요 없이, 원하는 샘플 칩을 원클릭하는 즉시 기준값 입력창에 자동 주입되어 오타 발생을 원천 차단.
* **0명 일치 감지 및 실시간 안전 토스트 경고 (`checkConditionMatchCount`):**
  - 사용자가 기준값을 입력하거나 변경할 때마다 전체 명단과 대조하여 일치하는 인원수를 실시간 검증.
  - 조건에 부합하는 인원이 0명인 경우 즉시 주황색 경고 토스트(`⚠️ 조건 일치 명단 0명: 해당 기준값과 일치하는 명단이 없습니다. (오타 또는 기준값을 확인하세요)`)를 띄워 빈 발송이나 헛걸음을 사전에 완벽 차단.

## 4. 무손실 영구 보관 및 템플릿 연동
* **F5 새로고침 복원 (`sensetalk_saved_condition`):**
  - 브라우저를 새로고침하거나 창을 닫았다 다시 열어도 설정된 필드명, 연산자, 기준값, 조건 활성화 토글 상태가 브라우저 LocalStorage에 안전하게 보존되어 100% 자동 복원.
* **템플릿 보관함(Save/Load) 완전 동기화:**
  - 상단 템플릿 저장 시 현재 활성화된 조건식 메타데이터가 메시지 블록과 함께 직렬화되어 영구 보관되며, 템플릿 불러오기 시 당시 설정된 발송 조건이 오차 없이 즉시 복원.

# PART 22. 미리보기 1:1 카카오톡 테스트 발송 및 대상 설정 엔진

## 1. 개발 배경 및 목적
* **사전 실전 검증 필요성:** 수십~수백 명에게 대량 연속 발송을 시작하기 전, 완성된 메시지(텍스트 치환 결과 및 이미지 블록)가 실제 PC 카카오톡 대화방에서 줄바꿈이 어떻게 깨지는지, 사진이 정상적으로 안착되는지 특정 대상 1명에게 안전하게 전송해보고 싶은 현장 니즈 충족.
* **마우스 0회 1:1 직통 발송:** 별도의 복잡한 절차 없이 미리보기 화면에서 버튼 1회 클릭만으로 실제 카톡 대화창을 즉시 띄우고 본문을 자동 장전.

## 2. 스마트 분할 버튼(Split Button) 인터랙션 아키텍처
* **좌측 메인 액션 영역:**
  - `[🧪 테스트 발송 (${savedName || '대상설정'})]` 버튼 본체.
  - 클릭 즉시 캔버스에 구성된 치환 텍스트와 이미지 블록을 해당 대상자의 카카오톡 대화방으로 즉시 주입.
* **우측 독립 설정 영역:**
  - `[⚙️]` 톱니바퀴 아이콘 버튼.
  - 메인 발송과 분리되어 언제든 클릭하여 대상 이름 변경 모달을 즉시 오픈.
* **미등록 시 지능형 자동 모달 오픈:**
  - 최초 실행 등 저장된 테스트 대상이 없는 상태에서 발송 버튼을 누르면, 에러 없이 자동으로 대상 설정 모달이 팝업되어 자연스러운 사용자 설정 동선 제공.

## 3. 사전 등록 가이드 및 나와의 채팅 차단 방어 (Anti-Failure Safeguard)
* **카카오톡 윈도우 구조적 한계 사전 방어:**
  - PC 카카오톡의 검색 아키텍처상 '나와의 채팅(내 프로필)'은 친구 검색창(`Ctrl + F`)에서 검색 결과로 노출되지 않음.
  - 사용자가 무심코 본인 이름을 적어 검색 실패를 겪지 않도록, 모달 내에 *"나에게 보내기(나와의 채팅)는 카카오톡 친구 검색창에서 검색되지 않으므로, 직원·동료 등 실제 등록된 친구 이름을 입력해주세요."* 명확한 사전 가이드 제공.

## 4. 엔진 연결 상태에 따른 지능형 버튼 제어 (금지 커서 배제)
* **엔진 미연결 시:**
  - 발송 본체 버튼은 반투명(50%) 처리 및 hover 시 "PC 엔진 연결 필요" 툴팁 표시.
  - 단, 대상 설정(`⚙️`) 버튼은 언제든 클릭 가능하여 엔진이 켜져 있지 않더라도 사전에 테스트 대상을 여유롭게 등록/수정 가능.
* **사용자 친화적 커서 경험:**
  - 사용자의 시각적 거부감을 유발하는 빨간색 금지 이모지나 `cursor-not-allowed`를 배제하고 자연스러운 포인터 커서로 정돈.

## 5. 실시간 1:1 캔버스 메시지 즉시 장전 파이프라인 (`/dispatch`)
* **개인화 치환 및 다중 블록 조합:**
  - 테스트 대상자의 이름을 기반으로 맞춤 변수(`#{이름}`)를 실시간 치환.
  - 본문 텍스트 블록과 등록된 이미지 블록들을 직렬화하여 로컬 가속 엔진의 `/dispatch` 엔드포인트로 전송.
* **단일 엔터 타건 발송:**
  - 로컬 엔진이 카카오톡 친구 검색(`Ctrl + F`) ➔ 1:1 대화방 진입 ➔ 텍스트 및 클립보드 비트맵(`CF_DIB`)을 차례대로 자동 주입.
  - 유저는 대화창을 확인하고 `[Enter]`만 치면 테스트 발송 완료.

# PART 23. 저장 대상 감지 시 주의 환기용 숨쉬는(Breathing) 애니메이션 효과

## 1. 개발 배경 및 목적
* **작업 유실 방지 및 시각적 피드백 강화:** 캔버스에서 메시지를 수정하거나 블록을 추가/삭제한 후 저장을 잊은 채 브라우저를 닫거나 다른 템플릿으로 전환하여 발생하는 작업 유실을 방지.
* **정적 UI 탈피:** 기존의 단순한 정적 색상 변화는 사용자의 시선을 효과적으로 끌지 못하고 멈춰있는 느낌을 주었으므로, 생동감 있게 주의를 환기하는 모션 인터랙션 도입.

## 2. 부드러운 호흡형 펄스 키프레임 애니메이션 (`@keyframes breathSaveBtn`)
```css
@keyframes breathSaveBtn {
  0%, 100% {
    transform: scale(1);
    box-shadow: 0 0 0 0 rgba(37, 99, 235, 0.45);
  }
  50% {
    transform: scale(1.025);
    box-shadow: 0 0 0 6px rgba(37, 99, 235, 0.15);
  }
}
```
* **시각적 특징:**
  - 2초 주기로 부드럽게 팽창(1.025배) 및 수축을 반복.
  - 외곽으로 퍼져나가는 푸른빛의 은은한 글로우 링(Glow Ring)을 통해 작업자가 "현재 저장할 변경사항이 있음"을 직관적으로 인지.

## 3. 상태 기반 자동 토글 라이프사이클
* **미저장 변경 감지 (`markUnsavedChange()`):**
  - 텍스트 수정, 블록 순서 변경, 블록 추가/삭제, 수신자 명단 편집 발생 즉시 저장 버튼이 파란색으로 활성화되며 숨쉬는 애니메이션(`animate-breath`) 자동 가동.
* **저장 완료 시 원복 (`saveCurrentTemplate()`):**
  - 저장이 성공하면 즉시 애니메이션이 해제되고 단정한 본래 상태로 복귀하여 깔끔한 작업 피드백 완성.
